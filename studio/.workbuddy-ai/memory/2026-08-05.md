## 字幕配置统一：高级剪辑复用 GlobalParamsVisualEditor 配置源

用户反馈：传递剪辑（AdvancedVideoEditor）跟模板混剪字幕位置/大小不一样，且成片位置也不一致。

根因：4 处硬编码字幕默认值（ExportPanelVFS 72/黄/18、editor-globals.css 写死的 bottom:7% 与 clamp 字号、VideoPreview 硬编码 index%15===0 换行），与 GlobalParamsVisualEditor.DEFAULT_CONFIG.subtitle（68/白/15）和 electron nativeCompose 的 getSubtitleAnchor 不一致。

修复：

1. 新建 `src/utils/subtitleConfig.js`：唯一权威的字幕配置源。
   - DEFAULT_SUBTITLE_CONFIG 与 GlobalParamsVisualEditor.DEFAULT_CONFIG.subtitle 字段一一对应（注释里写了：调整时务必同步两边）。
   - loadSubtitleConfig() 从 localStorage `rjcut_global_params_v1` 读取，与 BatchProcessor / GlobalParamsVisualEditor 共用同一存储键。
   - computeSubtitlePreviewStyle(subtitle, frameSize) 计算 React inline style，坐标换算公式与 electron/main.js getSubtitleAnchor 完全一致（baseYPercent、y_offset/2、translate(-50%,-50%) 等价于 ASS \an5 + \pos），保证预览 ↔ 成片位置一致。
   - getActiveSubtitleStyle() 高亮字样式覆盖。
   - splitSubtitleIntoLines(chars, maxCharsPerLine) 按配置切行，替代硬编码 15。

2. `src/components/VideoEditor/ExportPanelVFS.jsx` 264 行：硬编码 subtitleConfig（font_size:72、color:'#FFFF00'、max_chars_per_line:18）改成 loadSubtitleConfig()。

3. `src/components/VideoEditor/VideoPreview.jsx`：
   - 新增 useState 读 subtitleConfig，监听 storage 事件 + 500ms 轮询同步 GlobalParamsVisualEditor 的更新。
   - 新增 ResizeObserver 跟踪 .advanced-preview-frame 的实际尺寸（用于按比例缩放字号）。
   - 把字幕 div 拆出 SubtitleLayer 子组件，style 用 inline style（不再依赖 CSS 类）。
   - 换行从 `index % 15 === 0` 改成 splitSubtitleIntoLines(chars, max_chars_per_line)。
   - 高亮从 CSS `.is-active` 改成 inline style。

4. `src/components/VideoEditor/editor-globals.css` 597 行：删除 `.advanced-preview-subtitle` 的硬编码位置/字号/颜色/描边，只保留 white-space 与 word-break 兜底。

后续约定：
- 任何字幕样式默认值变更必须同时改 `src/utils/subtitleConfig.js` 的 DEFAULT_SUBTITLE_CONFIG 与 `src/components/GlobalParamsVisualEditor.jsx` 的 DEFAULT_CONFIG.subtitle，注释里有说明。
- 不要在高级剪辑这一路再起独立的字幕样式。
- 预览画布缩放基准是 frame 高度 / 1920，与 GlobalParamsVisualEditor 的 9/16 缩放策略一致。

## 模板混剪字幕源统一：localStorage 作为单一权威

用户新反馈：模板混剪抽屉里的预览位置（70%）和实际输出位置（55%）仍然不一样。截图证明同一段字幕在 GlobalParamsVisualEditor 内部预览里看到的是 y_offset=-40（→topPercent 70%），但 nativeCompose 出的成片是 y_offset=-10（→topPercent 55%）。

根因：之前虽然把 4 处硬编码消掉了，但"高级剪辑预览 / GlobalParamsVisualEditor / 原生合成" 这条链路**仍然读的是不同的源**：
- 高级剪辑 VideoPreview / ExportPanelVFS：读 `localStorage['rjcut_global_params_v1']`（subtitleConfig.js loadSubtitleConfig）。
- GlobalParamsVisualEditor（在 OutputSettingsDrawer / GlobalRenderSettingsStep 里）：被传 `value={draft.outputConfig?.globalParams}` + `persist={false} storageKey={null}`，**只写 draft，不写 localStorage**。
- localTemplateRenderer.js nativeCompose：读 `task.globalParams?.subtitle`，而 task.globalParams 又来自 `workingDraft.outputConfig?.globalParams`（即同一份 draft）。

结果：用户在抽屉里改的 subtitle 写到了 draft，但 preview / 原生合成 / 其他地方读的是 localStorage 或 task（不同时间点），三个源的 y_offset 就对不上。

修复（让 localStorage 成为唯一权威）：

1. `src/features/template-batch/OutputSettingsDrawer.jsx`：
   - 引入 `STORAGE_KEY as SUBTITLE_STORAGE_KEY`。
   - 挂载时（isOpen=true）做一次性 draft → localStorage 迁移：`localStorage.getItem(STORAGE_KEY)` 为空 + draft.outputConfig.globalParams 存在时把后者写进 localStorage，避免老数据丢失。
   - GlobalParamsVisualEditor 改为 `value={null} persist={true} storageKey={SUBTITLE_STORAGE_KEY}`，UI 与持久化都从 localStorage 拿。`onChange` 仍然同步更新 draft（其他下游场景仍可能读 draft.outputConfig.globalParams）。

2. `src/features/template-batch/steps/GlobalRenderSettingsStep.jsx`：同上，迁移 + persist=true + storageKey=SUBTITLE_STORAGE_KEY + value={null}。

3. `src/features/template-batch/localTemplateRenderer.js`：
   - 引入 `loadSubtitleConfig`。
   - 原生合成前合并：`{ ...draftSubtitle, ...subtitleFromStorage }`，让 localStorage 优先，draft 只作为兜底（兼容老任务、且 localStorage 还没迁移的情况）。这样输出位置和 GlobalParamsVisualEditor 内部预览一定一致。

4. `src/utils/subtitleConfig.js` 没有改动，但新增了 `STORAGE_KEY` 命名导出，方便其他文件引用同一个 key。

数据流修正后：
- GlobalParamsVisualEditor UI ↔ localStorage ↔ nativeCompose 字幕 ↔ 高级剪辑 VideoPreview 全部读 `rjcut_global_params_v1`。
- draft.outputConfig.globalParams 保留为任务快照（per-task override 入口），但默认从 localStorage 同步。

约定：
- 以后任何 GlobalParamsVisualEditor 的持久化场景都必须用 `SUBTITLE_STORAGE_KEY`（即 `rjcut_global_params_v1`），不要在抽屉/步骤组件里再写第二份默认值。
- 新增模板或场景级 override 时，写到 `task.globalParams.subtitle` 即可，会被 localTemplateRenderer 的合并逻辑覆盖。
